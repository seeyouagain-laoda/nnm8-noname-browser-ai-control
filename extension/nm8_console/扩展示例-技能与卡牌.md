- 引擎用 `GameEvent` 驱动，当前事件在 `_status.event`

  - 返回 `true` → 引擎**暂停等玩家输入**；返回 `false` → 引擎走内置 AI（`event.result = "ai"`，见 `content.js:4568`）
- 事件常用字段：`name` / `step` / `player` / `forced` / `filterCard` / `filterTarget` /

### ⚠️ 关键坑（本次踩出来的）
| 坑 | 说明 |
|---|---|
| 手动 `ui.selectCard()` 塞牌会崩 | 出牌 `chooseToUse` 必须走 `ai.basic.chooseCard/chooseTarget`，否则 `useCard` 读 `get.info(card).noai` 报 undefined（`player.js:7482`） |
| `ai1`/`ai2` 可能是 undefined | 直接传给 `ai.basic.chooseCard` 会抛 `check is not a function`（`ai/basic.js:122`），要提供默认值 |
| 没选到牌别点确定 | 求桃/弃牌没牌时必须 `cancel`，否则引擎拿到空结果永久卡在 `respond` |
| 引擎 `alert` 会阻塞渲染进程 | 未捕获异常弹窗后，CDP 连 `1+1` 都超时，必须拦截 |

## 二、扩展包标准结构（v1.75 ESM）

```
你的扩展/
├── info.json          ← 元信息
├── extension.js       ← 入口（对象式默认导出）
├── main/              ← 可选：内容拆分
│   ├── content.js
│   └── precontent.js
├── character/         ← 武将资源
├── card/              ← 卡牌资源
├── skill/             ← 技能资源
└── image/ audio/      ← 美术 / 语音
```

### `info.json`
```json
{
  "name": "你的扩展名",
  "author": "作者",
  "intro": "简介（支持 <li> 标签）",
  "version": "1.0",
  "diskURL": "",
  "forumURL": ""
}
```

### `extension.js`（官方标准写法）
```js
import { lib, game, ui, get, ai, _status } from "noname";
import { content } from "./main/content.js";
import { precontent } from "./main/precontent.js";

// 顶层 await 读 info.json，把元信息填进 package（扩展管理界面才能显示）
const extensionInfo = await lib.init.promises.json(
  `${lib.assetURL}extension/你的扩展名/info.json`
);

let extensionPackage = {
  name: "你的扩展名",
  config: {},                                        // 设置项
  content,                                           // 游戏内容：技能/卡牌/武将
  help: {},                                          // 帮助文本
  package: {},                                       // 由 info.json 填充
  precontent,                                        // 预加载（技能翻译、武将过滤等）
  files: { character: [], card: [], skill: [], audio: [] },
};

Object.keys(extensionInfo)
  .filter((key) => key !== "name")
  .forEach((key) => { extensionPackage.package[key] = extensionInfo[key]; });

export let type = "extension";
export default extensionPackage;
```

> ⚠️ 引擎 `game/index.js:2688` 也兼容**函数式导出**（会调用它拿返回值），
> 但官方 5 个内置扩展已统一为对象式，新扩展请照抄上面的写法。
> 若你的扩展需要在**主菜单阶段**就挂全局对象，记得在文件末尾显式初始化一次
> （对象式导出不会在加载期执行任何函数）。

## 四、技能

### 触发时机（`trigger`）
```js
trigger: {
  player: "useCard",   // 自己使用牌时
  global: "damage",    // 全场任何人受到伤害时
  source: "useCard",   // 自己作为伤害来源时
}
```
常用时机：`phaseBegin` / `phaseUse` / `phaseEnd` / `useCard` / `damage` /
`dying` / `die` / `gain` / `lose`

### 写法 A：传统 step（兼容性最好）
```js
let rende = {
  trigger: { player: "useCard" },
  filter(event, player) { return player.countCards("h") > 0; },
  content() {
    "step 0"
    if (player.countCards("h") > 0) { player.chooseToDiscard(1, true); }
    "step 1"
    player.draw(2);
  },
};
```

### 写法 B：async（v1.10.6+，推荐，可读性更好）
```js
let rende = {
  trigger: { player: "useCard" },
  filter(event, player) { return player.countCards("h") > 0; },
  async content(event, trigger, player) {
    if (player.countCards("h") > 0) { await player.chooseToDiscard(1, true); }
    await player.draw(2);
  },
};
```

### 技能 AI（**必写**，否则自动对局会卡住）
```js
let rende = {
  trigger: { player: "useCard" },
  async content(event, trigger, player) { /* ... */ },
  ai: {
    // 是否发动
    enable: "phaseUse",
    // 发动收益（>0 才发动）
    effect: { target(card, player, target) { return 1; } },
    // 出牌顺序
    order: 3,
  },
};
```
> **本次踩坑结论**：没有 AI 的技能，在自动/接管场景下会让引擎永久停在事件上
> （无 UI 选择器，点确定/取消/结束回合都无效）。写自定义技能务必补 `ai`。

## 六、调试与排障

| 现象 | 排查方向 |
|---|---|
| 技能不触发 | 检查 `trigger` 配置 + `filter` 条件 |
| 效果异常 | 检查 `content` 逻辑，用 F12 断点 |
| 自动对局卡死 | **十有八九是技能没写 `ai`**，或事件没有 UI 选择器 |
| 引擎弹窗卡死 CDP | 未捕获异常触发 `alert`；可在扩展里拦截 `window.alert` |
| 资源加载失败 | 确认 `files` 声明与 `image/` 路径 |
